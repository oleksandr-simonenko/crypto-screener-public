## 11. Контракт `export/flows_latest.json` для stage0 (С-26, 03.09.2026)

**Зачем.** Пятничный файл сегодня доезжает до stage0 руками пилота (документ в
Telegram → перекинуть в другой чат). Контракт ниже позволяет stage0 забирать его
без пилота: `git pull` клона этого репозитория → сверка отпечатка и формы по
`flows_latest.meta.json` → `Move-Item` к себе. Реализация забора — в пакете stage0;
здесь зафиксировано, ЧТО он забирает и КАК проверяет.

**Кто пишет.** `export_flows.py` (замороженный конвейер, пятница 08:17 UTC,
`export.yml`) пишет `export/flows_YYYYMMDD.json` и `export/flows_latest.json`
(одинаковое содержимое, `json.dumps(indent=1, ensure_ascii=False)`) и вызывает
`export_trades.export_all` → `export/flows_latest.csv` + `export/flows_latest.meta.json`.
Те же csv и meta пересобирает `metrics.yml` по пн/чт 07:17 UTC (json при этом не
меняется — меняется только провенанс meta).

**Версия формы — 1.** Ключа `schema_version` в самом json НЕТ (файл пишет
замороженный `export_flows.py`, править его до 15.11 нельзя). Версию объявляет
`export_trades.validate_flows` по результату проверки формы и кладёт в meta:
`source_schema_version: 1` при `source_valid: true`, иначе `null` и список
`source_problems`. Любое изменение формы (новый/пропавший ключ, другой тип) =
новая версия и правка `validate_flows`; неизвестный ключ верхнего уровня
валидатор считает проблемой намеренно — форма не должна меняться без версии.

**Схема json (версия 1):**

| Ключ | Тип | Смысл |
|---|---|---|
| `generated_utc` | строка `YYYY-MM-DDTHH:MM:SSZ` | момент экспорта (UTC) — **обязателен** |
| `source` | строка | подпись источника |
| `week_runs` | список строк `run_id` | прогоны скринера за 7 дней, вошедшие в топ |
| `note` | строка | пояснение экспортёра |
| `top_contracts` | список объектов — **обязателен** | монеты топ-15 прогонов недели, **дедуп по `cg_id`** (тикеры не уникальны), от большего `score` к меньшему |
| `top_contracts[i].ticker` | строка | тикер |
| `top_contracts[i].cg_id` | строка, непустая, уникальная | ключ CoinGecko — ключ склейки обоих проектов |
| `top_contracts[i].run_timestamp` | строка `YYYY-MM-DDTHH:MM:SSZ` | прогон, где монета была в топе последний раз |
| `top_contracts[i].score` | число или `null` | балл скринера |
| `top_contracts[i].mcap_usd`, `.price_usd` | число или `null` | капитализация и цена на момент прогона |
| `top_contracts[i].entered_paper` | булево | вошла ли в бумажный портфель |
| `top_contracts[i].contracts` | объект `{сеть: адрес}` | адреса по сетям CoinGecko; пусто = нативная монета или контракты не отдались |
| `blacklist` | объект `{ТИКЕР: {reason, event_date}}` — **обязателен** | снапшот чёрного списка; `event_date` — `YYYY-MM-DD` или `null` (дата не подтверждена — карантин бессрочный) |

**Отпечаток и дата — в `export/flows_latest.meta.json`** (рядом с провенансом csv):
`source_json`, `source_generated_utc` (= `generated_utc` json), `source_bytes`,
**`source_sha256`** — sha256 LF-нормализованных байтов json (**канон**, равен
`git show <коммит>:export/flows_latest.json | sha256sum`), `source_sha256_raw`
(как файл лежал у экспортёра), `source_crlf` (был ли CRLF — в дереве пилота на
Windows да, на раннере нет), `source_schema_version`, `source_valid`,
`source_problems`, `source_contract` (ссылка сюда); `provenance.generated_utc`
meta — когда meta пересобран.

**Как забирать (сторона stage0, реализация в её пакете):**
1. `git pull --ff-only` клона `crypto-screener`;
2. прочитать `export/flows_latest.meta.json`; сверить `source_sha256` с sha256
   LF-нормализованных байтов `export/flows_latest.json` (на Windows с autocrlf
   файл CRLF — нормализовать перед хешем); при расхождении — не забирать (json и
   meta из разных коммитов: json обновляется пятницей, meta — пятницей и пн/чт);
3. забирать только при `source_valid == true` и `source_schema_version == 1`;
   дата свежести — `source_generated_utc` (ожидать пятницу текущей недели);
4. `Move-Item`/копия к себе с именем по `source_generated_utc`; при
   `source_valid == false` — печатать `source_problems` и ждать пилота.
Сторож контракта здесь — `tests/test_export_rotate.py::TestFlowsContract`
(в том числе: боевой `flows_latest.json` проходит валидацию версии 1; копии LF и
CRLF дают один канонический отпечаток).
